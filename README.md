# Linux.do 自动浏览+点赞的油猴插件

> 本项目由 [https://github.com/xiaowanjiagit/linuxdo](https://github.com/xiaowanjiagit/linuxdo) 修改而来，在原版基础上持续优化与修复。

## 功能特性

- **自动浏览话题列表** - 支持 /latest, /new, /unread, /top, /hot 等页面
- **分区浏览** - 「选分区…」弹出独立窗口勾选只浏览哪些板块（默认与 dosss 一致勾选 12 个常用分区），勾选后自动浏览只在所选分区内轮换找帖；也可选「不限分区」按未读/新帖/最新全站轮换
- **无限滚动加载** - 自动滚动加载更多话题和回复
- **智能去重** - 已浏览帖子标记存储，避免重复浏览
- **完整回复浏览** - 帖子详情页滚动浏览所有回复直到底部
- **自动循环** - 浏览完成后自动返回列表继续下一个未浏览话题
- **随机点赞** - 按概率随机点赞（概率低/中/高/极高可在面板调节），带间隔控制；可勾选「只赞主帖」仅给楼主帖点赞、跳过回复楼层
- **楼层限制** - 可设定每帖只浏览前 N 楼后换下一帖，并可选择只按未读楼层计数
- **断点续读** - 进入读过一部分的帖子时自动点击时间线「返回」，跳回上次读到的楼层继续
- **每日定时** - 面板可设定每天到点自动开始新一轮浏览，时间可调；修改时间即自动开启定时，重新设置后当天仍可触发（不再被「今天已跑过」吞掉）
- **会话目标** - 可设定本轮浏览满 N 帖 / 点满 M 赞自动停止（0 表示不限），**浏览与点赞都达标才收尾**；可另设单次运行时长上限（分钟，0 不限），超时自动停止；目标按「刷帖数」计（浏览的话题个数），翻楼/阅读楼层不计入，面板实时显示目标进度；**全部目标为 0 时禁止开始**（强制至少设一个目标，避免无限目标）
- **高级设置** - 「⚙ 高级设置」按钮展开 9 项数值参数（翻页步长/间隔、加载等待、阅读时长、点赞概率/间隔、返回延迟、滚动抖动），留空即跟随当前速度/概率预设，填数值立即生效并记忆
- **反检测随机节奏** - 一次滚动拆成 2~4 段小步连续下滑（段间随机停顿，视觉上连续不「一跳一跳」）、步长随机抖动 ±60px、到达页底改为轮询等待新内容（不再干等）、点赞前随机思考停顿 300-900ms、延迟区间加宽，避免恒定节奏的机械感
- **阅读量统计** - 监听 /topics/timings 阅读上报接口，面板实时显示本次阅读楼层数与目标进度，页面刷新不清零
- **可视化控制面板** - 双列布局更紧凑，实时显示状态和统计数据，默认收起为悬浮球，可拖动到页面任意位置
- **半透明信息浮窗** - 面板内不再显示统计信息（仅保留设置区）；可选开启后由页面左上角半透明浮窗实时显示（状态/页面类型/浏览/点赞/阅读楼层/目标进度/定时/**限时剩余/当前时间**，时钟实时走秒），可按住拖到任意位置、松手自动记忆位置；关闭浮窗则任何位置都不显示统计信息
- **视觉标记** - 已浏览话题显示绿色勾号，透明度降低
- **配置灵活** - 所有参数可调整

## 快速开始

1. 安装 [Tampermonkey](https://www.tampermonkey.net/) 浏览器扩展
2. [**点此一键安装**](https://raw.githubusercontent.com/yyyyy114514/getldc/master/src/linuxdo-automation.user.js) —— Tampermonkey 会自动弹出安装确认页（也可手动新建脚本，复制 `src/linuxdo-automation.user.js` 内容）
3. 访问 https://linux.do 并登录
4. 页面右下角会出现紫色悬浮球，点击展开控制面板（拖动可移到任意位置）
5. 按需设置速度、列表、点赞与楼层限制，点击"开始自动浏览"

脚本已声明 `@updateURL`，安装后 Tampermonkey 会自动检查更新；`@name` 不含版本号，升级时直接覆盖安装即可。

### v2.7.1 (2026-09-27)
- **优化** - 人化算法行为序列更「连贯真实」，四项新随机维度（全部只作用于人化模式）：
  - **节奏多日自相关**：τ 不再每天独立重抽（白噪声式跳变本身就是机器特征）——60% 概率在昨日 τ 的 ±20% 内扰动，40% 全新抽取，连续几天节奏大体接近、偶尔大幅变化，贴近真人作息惯性
  - **沉浸帖**：约 20% 的帖子触发「沉浸阅读」，阅读投入度抽到 1.6~2.4×（其余 0.7~1.3×），遇到感兴趣的长帖会读得明显更久
  - **中途离场**：约 15% 的帖子读到 55%~85% 楼层就返回列表（真人很少帖帖读完）；总楼数未知的帖子仍读完全程，目标进度不受影响
  - **点赞犹豫**：约 30% 概率点赞前先滚动离开按钮（像滑走再看一眼）、停顿片刻再滑回来点击，偶发「先走再回」是典型真人手部动作
- **修复** - 人化专属设置区改为纵向分排（时段/浏览目标/点赞目标/时长上限各行独立），不再挤成一行

### v2.6.9 (2026-09-27)
- **变更** - 反指纹大修（站长视角自查，消除三处服务端可验证的机器特征）：
  - 彻底移除对 `fetch`/`XMLHttpRequest` 的网络拦截（原用于监听阅读上报）：包装浏览器原生函数会在页面里留下可验证的指纹（`fetch.toString()` 能看到包装痕迹，站点 JS 一查便知是脚本）。阅读楼层统计改为**纯 DOM 逐楼计数**，与网络层完全解耦
  - 话题进入/返回改为**点击式 Ember SPA 导航**：真人点话题链接走客户端路由（`pushState` 改 URL + XHR 拉 `/t/topic/{id}.json`），而脚本此前每次 `location.href` 整页跳转，会在服务端访问日志里留下「全站浏览零 JSON、全是整页 HTML」的强指纹。现在点击真实链接：Ember 拦截则 SPA 跳转（URL 变化由 `checkUrlChange` 接管换浏览器），未被拦截则照常整页导航，点击无效 1.2s 后兜底整页跳转——三种结局都安全；从话题返回列表同理，优先 `history.back()` 走 SPA popstate
  - 点赞间隔去掉「绝不下限」的硬门槛：真人点赞分布里偶发 1 秒内快速连赞，恒定的 ≥2000ms 下限本身就是统计指纹。改为软性：绝大多数维持最小间隔，约 8% 概率放行一次 ≥400ms 的连赞（过快仍由 429 风控兜底自动关点赞）
- **修复** - SPA 进入话题时 `#data-preloaded` 仍是列表页数据（无 `topic_` 键），`getTopicTotalPosts` 误读为 0 会白等不存在的楼：新增页面进度条 `#topic-progress-total` 兜底，SPA 路由进入也能拿到真实总楼数

### v2.6.8 (2026-09-27)
- **新增** - 反检测大修：行为节奏全面人化，长时间序列不再暴露机器人统计特征——
  - 延迟分布偏态化：所有「思考/阅读/滚动/离帖」停顿从均匀随机改为偏态分布（多数偏短、偶发明显偏慢），不再每个间隔都落在固定区间的均匀带里
